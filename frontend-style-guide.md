# Стиль фронтенду — довідка перед генерацією нового UI

Цей файл — не план фіч, а фіксація ВІЗУАЛЬНОГО й UX-стилю, який уже
встановлено в грі й повторюється екран за екраном. Перед тим, як
проєктувати/переробляти будь-який екран, звіряйся з цим файлом — мета:
жоден новий шматок інтерфейсу не повинен виглядати "чужим" на фоні решти.

Еталон живого прикладу — `MenuScreen.jsx` + `src/index.css`. Якщо
сумніваєшся, як має виглядати новий елемент — подивись, чи є вже схожий
там, і перевикористай клас, а не вигадуй новий з нуля.

## 1. Загальний візуальний характер

- Фентезі-RPG для дітей, не корпоративний UI: темно-індигово-фіолетова
  палітра, золоті акценти, "намальовані" (painted) іконки замість плоских
  SVG, м'які світіння/тіні замість різких плоских країв.
- Базовий фон сторінки — `#1e1338`, ніколи не білий/сірий.
- Шрифти: `Cinzel` (`.font-display`) для заголовків/цифр/кнопок — з
  letter-spacing, "гравірований" вигляд; `Baloo 2` (`.font-body`) для
  звичайного тексту/пояснень — округлий, дружній, дитячий.
- Золотий "гравірований" текст (`.gold-text`) — для головних чисел і
  заголовків, які мають виглядати як нагорода/цінність (відсоток
  засвоєння, XP, ключові заголовки).

## 2. Базові будівельні блоки (перевикористовувати, не дублювати)

- **Панель** — `.rpg-panel` (напівпрозорий фіолетовий градієнт + тонка
  золота рамка + м'яка тінь) для будь-якого інформаційного блоку.
  `.rpg-panel-gold` — акцентований варіант із яскравішою рамкою й
  зовнішнім сяйвом, коли панель має привертати увагу першою.
- **Кнопки — дві родини, ніколи не змішувати без причини:**
  - Золота головна дія (`.next-challenge-button` / `.play-button` /
    спеціалізовані варіанти на кшталт `.knowledge-cta-button`) — товста,
    багатошарова (градієнт + зовнішній контур + внутрішній глянець
    зверху + натискний стан з translateY), лише ОДНА на екран.
  - Фіолетова другорядна дія (`.knowledge-secondary-button` і подібні) —
    менш акцентна, для "додаткової", не головної дії (закрити,
    продовжити, повторити).
  - Текст на золотій кнопці — темно-фіолетовий (`text-indigo-950`), НЕ
    дрібний білий/світлий — інакше контраст на золотому фоні страждає.
  - Кожна кнопка має власний `:active`-стан (translateY/scale), інколи
    `:hover` (лише під `@media (hover: hover)`, щоб не "залипало" на
    тач-екранах) і `:focus-visible` для клавіатурної навігації.
- **Картки/рядки списків** — тонка золота рамка (навмисно ТОНКА, не
  товста — статус передає іконка+текст+бар, не суцільна кольорова
  заливка картки), м'яка тінь, легкий підйом на hover, натискний стан.
- **Прогрес-бари** — темний матовий трек, кольоровий градієнт заповнення
  за змістом (не завжди золото — колір відповідає статусу/тіеру), легкий
  верхній глянець і м'яке світіння на краю заповнення для "товстих"
  версій (зведені панелі); анімоване заповнення при відкритті екрана
  (scaleX 0→1), а не миттєва поява на всю довжину.
- **Іконки статусу** — реальні "намальовані" PNG (через `ArtImage` з
  emoji-фолбеком, якщо файл відсутній), не голі emoji як основний
  варіант.

## 3. Кольорова мова статусу/зворотного зв'язку

- Правильно / добре / майстер → смарагдово-золоті відтінки (`emerald`,
  `#10b981`, золото).
- Неправильно / потребує уваги → М'ЯКИЙ кораловий/рожевий акцент
  (`rose-200`, `coral outline`), а не суцільна яскраво-червона заливка.
  Суцільний тривожний червоний (`#e11d48` fill) дозволений лише для
  фінального/останнього стану помилки після повторної спроби — не для
  першої помилки і не для постійних бейджів/дій.
- **Статус ніколи не передається лише кольором** — завжди разом з
  іконкою, назвою і числом/поясненням (доступність + діти зі
  сльпотою до кольору).
- Проміжний стан ("майже", "непогано") має СВОЄ власне, м'якше
  формулювання — ніколи не перевикористовувати слово "повторити"/
  "погано" для проміжного результату; це для справді слабкого стану.

## 4. Тон і мова для дитини

- Завжди дружній, підбадьорливий, ніколи не звинувачувальний. Дитину не
  називати "слабкою"; приклад/факт може бути "недостатньо закріплений",
  не "поганий".
- Помилка — можливість спробувати ще раз і отримати підказку, не привід
  для тривожного/агресивного оформлення (без миготіння червоним, без
  "Неправильно!" великими літерами).
- Технічні деталі (сирі відсотки, лічильники спроб, внутрішні тіери) —
  для дорослого/дебаг-контексту; дитині показувати людське пояснення
  ("Останнього разу було непросто", а не "accuracy 42%").

## 5. Взаємодія й мікроанімації

- Кожна значуща дія (клік, правильна/неправильна відповідь, нагорода) —
  короткий звук (`sfx.js`) і, де доречно, коротка анімація (іскри,
  сяйво тіера, тремтіння при помилці) — але коротка, без довгих затримок
  перед продовженням гри.
- Помилка не повинна миттєво "проковтувати" прогрес чи миттєво
  перемикати екран — дай дитині побачити, що сталось (підказка →
  повторна спроба → повне пояснення → явна кнопка "Продовжити" на
  останньому кроці).
- Прогрес усередині короткого тренування/квізу — сегментований індикатор
  (ромби/пігулки: пройдено/поточний/майбутнє), не голий текст
  "Приклад X з Y" як єдина індикація.

## 6. Компонування й типографіка

- Одна головна дія на екран (одна золота кнопка), решта — другорядні.
- Заголовок екрана + короткий підзаголовок-пояснення під ним (не занадто
  довгий, коротший варіант на вузьких екранах через `sm:hidden`/
  `hidden sm:inline`).
- Числа/відсотки і бейджі-рекомендації — НІКОЛИ не накладати абсолютним
  позиціюванням поверх тексту/іконки картки; усе в звичайному потоці
  верстки (flex/grid), щоб нічого не перекривалось на вузьких екранах.
- Не притискати текст до самих країв панелей (grid/gap замість голого
  `justify-between` на 2 елементи, коли інформації більше).

## 7. Мобільна/доступність — жорсткі мінімуми

- Тапабельна висота рядка/картки — мінімум 72px.
- Важливий текст — не менше 14px.
- Кнопки відповіді у квізах — не нижче 72px.
- Головні кнопки не повинні перекривати контент і мають враховувати
  safe-area знизу.
- На планшеті — обмежити максимальну ширину контенту, центрувати, не
  розтягувати картки на всю ширину.
- Кожен інтерактивний елемент — `aria-label`, коли текст сам по собі не
  описує стан повністю (напр. картка статусу з іконкою+відсотком).

## 8. Узгодженість цифр

- Якщо екран показує "N завдань"/"N хвилин" — ця цифра МАЄ рахуватись
  тією самою функцією, яка реально будує сесію/пул (не окремою
  копією-наближенням) — інакше цифри розходяться між екранами.
- Форматування відсотків/часу/кількості спроб — через єдиний спільний
  хелпер (`src/game/format.js`), не локальні дублікати на кожному
  екрані (українська кома в часі, не крапка).

## 9. Коли додаю щось нове

1. Спочатку шукаю існуючий клас/патерн (`rpg-panel`, `knowledge-*`,
   `answer-btn*`, `next-challenge-button` тощо) — новий CSS-клас пишу
   лише якщо справді немає відповідного.
2. Якщо роблю кілька екранів одного сценарію (як три екрани "Мої
   знання") — вони мають ДІЛИТИ одні й ті самі компоненти/класи
   (заголовок, картка, прогрес-бар, кнопки), а не отримувати кожен свій
   ad-hoc стиль.
3. Перевіряю: чи не передаю статус лише кольором, чи є дружнє
   формулювання замість технічного/тривожного, чи не порушені мобільні
   мінімуми з розділу 7.
