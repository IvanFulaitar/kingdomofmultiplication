# Королівство Математики

Браузерна фентезі-RPG для дітей: подорож картою королівства, бої з монстрами
через математичні приклади, магазин аватарів, досягнення й три додаткові
режими тренування. Зараз усі приклади — таблиця множення (2–9); гра
навмисно спроєктована так, щоб надалі прийняти й інші теми математики (див.
`roadmap-kingdom-of-mathematics.md`).

## Що вже є в грі

- **Перший запуск** — новий гравець (без прогресу) бачить короткий
  онбординг замість одразу головного екрана: коротке знайомство, вибір
  навчальної впевненості (не вік/особисті дані), 10-прикладна діагностика
  без штрафів і короткий інтерактивний tutorial-бій. Показується рівно
  один раз; наявні гравці цього екрана не побачать.
- **Основна подорож** — карта з 4 регіонів (Ліс Новачків, Гори Хоробрих,
  Замок Майстра, Вежа Мудреця), 12 рівнів-боїв із монстрами, зірки за
  безпомилкове проходження, XP і рівень героя.
- **Магазин** — 16 аватарів за монети, з підтвердженням покупки в окремій
  модалці.
- **Досягнення** — бейджі за перемоги, серії без помилок, повне проходження
  регіонів тощо.
- **Мої знання** — окремий розділ прогресу (не тренувальний режим), три
  екрани одного навчального сценарію ("побачив прогрес → знайшов слабке →
  потренував → побачив покращення"), не просто список відсотків:
  - Зведена панель зверху: загальне засвоєння з анімованим прогрес-баром,
    три рядки розподілу таблиць (добре знаю / майже засвоєно / потрібно
    повторити) і клікабельна рекомендація, яку таблицю варто
    покращити/повторити чи почати наступною (текст завжди узгоджений зі
    статусом — "покращити" для проміжного рівня, "повторити" лише для
    справді слабкого).
  - 8 карток таблиць (2–9) зі статусом (⚪ ще не вивчалось / 🔴 потрібно
    повторити / 🟡 майже засвоєно / 🟢 добре засвоєно / ⭐ майстер),
    відсотком і прогрес-баром; перемикач сортування "За номером" /
    "Найслабші спочатку".
  - Детальний перегляд обраної таблиці — усі 8 прикладів окремо, чітко
    відрізняються "недостатньо даних" (щойно зустрінуті) від уже оцінених;
    дружній клікабельний бейдж "Потренувати" на найслабших запускає
    тренування саме цього прикладу; розгорнутий рядок показує статистику,
    навчальну підказку і кнопки "Потренувати цей приклад"/"Закрити".
  - "Майстер" — не лише високий відсоток: потрібні ще й достатня
    кількість спроб, стабільна серія без помилок і впевнений час
    відповіді. Одна випадкова помилка після довгої серії плавно знижує
    статус, а не миттєво обвалює його (згладжена оцінка).
  - Кнопка тренування (весь набір слабких, конкретна таблиця чи один
    приклад) запускає коротке прицільне тренування (6-8 прикладів,
    цифра на екрані завжди точно збігається з реальною довжиною сесії);
    перша помилка дає підказку й повторну спробу, друга — повне пояснення
    з кнопкою "Продовжити"; підсумок показує зміну "було → стало" і на
    рівні таблиці, і на рівні кожного окремого прикладу, найкращу серію й
    точність.
  - Головний вхід — картка в сітці 2×2 на головному екрані (разом із
    "Досягнення"/"Магазин"/"Тренування"), з бейджем "Нове" при свіжій
    активності; додатково відкривається через панель героя ("Прогрес") і
    другорядне посилання на сторінці "Тренування".
- **Тренування** — три додаткові режими поза основною картою:
  - *Математична пам'ять* — знайди пари "приклад ↔ відповідь".
  - *Лабіринт* — розгалужена мандрівка клітинками з ключами, скринями,
    пастками й порталами; складність зростає з кількістю пройдених спроб.
  - *Перегони* — перегони із двома суперниками; перед стартом гравець сам
    обирає складність (Тренувальний / Пригодницький / Чемпіонський заїзд) —
    кожна дає інший темп суперників і іншу нагороду, а чемпіонський
    відкривається після перемоги у пригодницькому або 5-го рівня героя.
- **Звук** — фонова тема (безшовний луп через Web Audio) і бібліотека з
  36 коротких ефектів, з окремими тумблерами "Музика"/"Звуки" в налаштуваннях
  головного екрана.
- **Єдина дизайн-система** — темно-індигово-фіолетові панелі з тонкою
  золотою рамкою, дві родини кнопок (золота головна / фіолетова другорядна),
  спільна для всіх екранів; головний екран (`MenuScreen.jsx`) — візуальний
  еталон, до якого підтягнуті решта екранів.

## Запуск локально

Потрібен встановлений [Node.js](https://nodejs.org) (18+).

```bash
npm install
npm run dev
```

Відкриється адреса на кшталт `http://localhost:5173` — гра запуститься
в браузері з "живим" перезавантаженням при зміні коду.

Для збірки готової статичної версії (яку можна викласти на будь-який
хостинг — Vercel, Netlify, GitHub Pages тощо):

```bash
npm run build
```

Результат з'явиться в папці `dist/` (не в репозиторії — вона в `.gitignore`).

## Збереження прогресу й налаштувань

Усе зберігається в **`localStorage`** браузера — прогрес нікуди не зникає
між заходами на тому самому пристрої/браузері:

- `kingdom-multiplication-progress` — основний прогрес (`src/game/progress.js`):
  монети, XP, зірки за рівні, бейджі, історія останніх 5 заїздів "Перегонів"
  (для рекомендації складності), особисті рекорди.
- `musicEnabled`, `musicVolume`, `sfxEnabled`, `sfxVolume` — окремі
  налаштування звуку (`src/game/music.js`, `src/game/sound.js`).
- `raceDifficulty` — остання обрана складність "Перегонів" (лише підказка
  для наступного відкриття — екран вибору показується завжди).

Прогрес має `saveVersion` і просту систему міграцій (`migrateSave()`), тож
зміна структури збереження в майбутньому не губить старі дані. Перед кожним
записом попередній валідний стан копіюється в `kingdom-multiplication-progress-backup`;
якщо основний запис пошкодиться (наприклад, вкладку закрили посеред запису),
гра автоматично відновлює прогрес із цієї копії й показує про це коротке
повідомлення. У налаштуваннях головного екрана (значок 🔊/🔇) також є
"Експортувати прогрес" / "Завантажити збереження" — власний JSON-файл на
випадок очищення сховища браузера чи переносу на інший пристрій, до появи
серверних акаунтів (див. `backend-architecture-plan.md`).

Глобальний `ErrorBoundary` (`src/components/ErrorBoundary.jsx`) перехоплює
неспіймані помилки рендера — замість білого екрана дитина бачить зрозуміле
повідомлення й кнопки "Перезапустити" / "Повернутися на головну".

## Графіка й звук

Компонент `ArtImage` (`src/components/ArtImage.jsx`) тихо замінює будь-яку
картинку на emoji-заміну, якщо файл відсутній (404) — нічого не ламається.
Практично всі очікувані файли вже є в `public/assets/`; актуальний перелік
папок і призначення файлів — у `public/assets/README.md`.

Фонова музика — `public/assets/audio/music/`, ефекти — `public/assets/audio/sfx/`.

## Дизайн-система

Головний екран (`MenuScreen.jsx`) — візуальний еталон. Базові класи в
`index.css` (`.rpg-panel` / `.rpg-panel-gold`, `.play-button` /
`.next-challenge-button` / інші кнопки, `.modal-panel` / `.exit-modal-panel`)
перевикористовуються майже на кожному екрані — зміни там автоматично
підхоплюються всюди, тож перед правками панелей/кнопок варто спершу
перевірити, чи не спільний це клас.

## Плани на майбутнє

**`backend-mvp-plan.md` — найвищий пріоритет зараз.** Легкий бекенд
(Express + PostgreSQL + Prisma, JWT-автентифікація email/пароль),
задеплоєний на Railway, щоб уже почати збирати користувачів. Вузький,
дійовий перший крок — лише таблиця `users` і реєстрація/логін, без
переробки пізніше під повнішу схему.

**`android-play-store-plan.md` — наступний етап, ПІСЛЯ бекенду.** План
публікації в Google Play через Capacitor (React/Vite-збірка → Android
Studio → підписаний `.aab` → Play Console): підготовка, Capacitor,
signed build, сторінка застосунку, дитяча аудиторія/Data Safety/Privacy
Policy/видалення акаунта, internal + closed testing (12 тестувальників
/ 14 днів), Production. Не починати, поки логін/реєстрація/серверне
збереження й HTTPS не готові — тестування на телефоні й Data Safety
залежать від цього.

**`launch-plan.md` — головний план дій для самої гри.** Усе, що потрібно
закрити перед публічним запуском (надійність збереження, якість
навчання, перший запуск/onboarding, приватність, доступність,
продуктивність, PWA, тестування) — з чіткими пріоритетами P0/P1/P2. Нові
фічі й контент чекають, поки не закриті пункти звідти.

Довгостроково, вже після цього плану: `roadmap-kingdom-of-mathematics.md`
(розширення теми — дроби, рівняння, відсотки тощо для 5–6 класу) і
`improvement-plan.md` (старіший, менш пріоритетний список ідей —
здебільшого вже покритий/уточнений у `launch-plan.md`).

Окремо — `backend-architecture-plan.md`: довідковий план ПОВНОЇ серверної
архітектури гри (NestJS, profiles, game_saves, покупки, статистика
прикладів тощо), коли прогрес переїде з `localStorage` на сервер повністю.
`backend-mvp-plan.md` вище — навмисно вужчий перший крок до нього (та
сама БД і хостинг, легший фреймворк, лише автентифікація), не заміна.

Інші ідеї для продовження:
- Дістати чисту логіку з `game/` (без React) в окремі unit-тести (Vitest/Jest).
- Винести кольори/шрифти з `index.css` у `tailwind.config.js` (`theme.extend`),
  якщо захочеться змінювати палітру з одного місця.
