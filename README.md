# Королівство Множення

Браузерна гра для дітей 5–6 класу: таблиця множення, а після проходження
Замку Майстра — комбіновані вирази на кілька дій (×, +, −).

## Структура проєкту

```
src/
├── main.jsx              точка входу (монтує App у #root)
├── index.css             Tailwind + шрифти + всі keyframes-анімації
├── App.jsx                стан гри, маршрутизація між екранами
├── data/
│   ├── regions.js         регіони, рівні, монстри, isLevelUnlocked
│   ├── cosmetics.js       аватари й рамки профілю (магазин)
│   └── rewards.js         бейджі досягнень і щоденні завдання
├── game/                  чиста логіка, без React — легко тестувати окремо
│   ├── generateQuestion.js  генерація прикладів (класичні + комбіновані)
│   ├── memory.js            генерація карток для "Математичної пам'яті"
│   ├── progress.js          збереження/завантаження, XP, стрік, квести
│   └── random.js             rand() і shuffle()
├── components/            дрібні перевикористовувані елементи
│   ├── Heart.jsx, StarIcon.jsx, Coin.jsx, TopBar.jsx
│   ├── BadgesModal.jsx, BadgeToast.jsx
└── screens/                екрани на весь розмір
    ├── MenuScreen.jsx, MapScreen.jsx, GameScreen.jsx, ResultsScreen.jsx
    ├── ShopScreen.jsx, TrainingScreen.jsx, MemoryScreen.jsx
```

## Запуск локально

Потрібен встановлений [Node.js](https://nodejs.org) (18+).

```bash
npm install
npm run dev
```

Відкриється адреса на кшталт `http://localhost:5173` — гра запуститься
в браузері з "живим" перезавантаженням при зміні коду.

Для збірки готової статичної версії (яку можна викласти на будь-який
хостинг — Vercel, Netlify, GitHub Pages тощо):

```bash
npm run build
```

Результат з'явиться в папці `dist/`.

## Важливо: збереження прогресу

Гра зберігає прогрес у **`localStorage`** браузера (файл `src/game/progress.js`).
Це звичайний, стандартний спосіб для реальних сайтів — прогрес зберігається
на тому пристрої й у тому браузері, де грали, і не зникає між заходами.

(Якщо ви бачили цю гру раніше як Claude-артефакт у чаті — там для збереження
використовувався спеціальний `window.storage`, який працює лише всередині
Claude. Тут, у звичайному проєкті, це вже не потрібно.)

## Графіка: як підкласти справжні ілюстрації

Зараз усі персонажі й монстри — emoji у декоративних панелях (золоті рамки,
зоряне небо, банери — усе на CSS, без картинок). Компонент `ArtImage`
(`src/components/ArtImage.jsx`) вміє тихо замінити emoji на справжній файл,
щойно той з'явиться:

```
public/assets/avatars/wizard.png   → аватар героя
public/assets/monsters/7.png       → монстр рівня 7 (номер = ID рівня)
public/assets/frames/gold.png      → рамка профілю (наразі рамки — CSS ring,
                                      цей шлях зарезервовано на майбутнє)
public/assets/backgrounds/A.png    → фон регіону A
```

Повний список очікуваних назв — у `public/assets/README.md`. Просто
згенеруй картинки (Midjourney/DALL·E/будь-де) чи замов художнику, поклади
з тими самими назвами — і код підхопить їх сам, без жодних правок.

## Де зараз "не готово"

У `TrainingScreen.jsx` дві плитки — "Лабіринт" і "Перегони" — позначені
"Скоро" і не мають логіки. Вони навмисно залишені як видимі заглушки,
щоб було зрозуміло, куди їх додати.

## Ідеї для продовження

- Дістати `game/generateQuestion.js` і `game/memory.js` в окремі unit-тести
  (це чисті функції без React — ідеально підходять для Vitest/Jest)
- Додати `game/maze.js` і екран `screens/MazeScreen.jsx` за тим самим
  принципом, що й `MemoryScreen.jsx`
- Винести кольори/шрифти з `index.css` у `tailwind.config.js` (`theme.extend`),
  якщо захочеться змінювати палітру з одного місця
