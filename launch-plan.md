## 1. Правильно позиціонувати перший реліз

Назва «Королівство Математики» обіцяє багато різних математичних тем, але
зараз фактично доступна лише таблиця множення 2–9. Не потрібно чекати,
поки будуть готові всі 100+ рівнів. Першу версію краще представити так:

> **Королівство Математики**
> Розділ 1: Магія множення

або:

> **Королівство Математики: Таблиця множення**

На карті можна показати майбутні закриті світи:

- Місто Великих Чисел — скоро.
- Острів Дробів — скоро.
- Долина Рівнянь — скоро.
- Геометричний архіпелаг — скоро.

Так користувач бачить масштаб гри, але не відчуває, що йому пообіцяли
весь курс 5–6 класу, а дали тільки множення.

## 5. Перетворити тренування на справжню систему навчання

Зараз гра добре тренує швидке відтворення відповідей, але для повноцінного
навчального продукту потрібен не тільки drill.

### Для кожної пари множення зберігати

Наприклад, для 7 × 8:

```json
{
  "attempts": 14,
  "correct": 9,
  "incorrect": 5,
  "averageResponseTime": 4.2,
  "lastAnsweredAt": "...",
  "correctStreak": 2,
  "mastery": 61
}
```

### Система повинна враховувати

- відсоток правильних відповідей;
- швидкість відповіді;
- скільки часу минуло після останнього повторення;
- останні помилки;
- кількість правильних відповідей поспіль.

### Пріоритет прикладу

Умовно:

```
пріоритет =
  помилки
  + повільні відповіді
  + давно не повторювалося
  - стабільна серія правильних відповідей
```

Слабкі приклади мають з'являтися частіше, але не настільки часто, щоб
дитина бачила одне й те саме п'ять разів поспіль.

### Додати статус засвоєння

Для кожної таблиці:

- 🔴 Потрібно потренувати.
- 🟡 Майже засвоєно.
- 🟢 Добре знаю.
- ⭐ Майстер.

Це можна показати у спеціальному екрані «Мої знання».

## 6. Додати пояснення після помилки

Найбільша навчальна прогалина — відповідь «правильно/неправильно» без
пояснення.

Для прикладу 7 × 8 після другої помилки можна показати:

> 7 × 8 — це сім груп по вісім.
> 7 × 5 = 35
> 7 × 3 = 21
> 35 + 21 = 56

Або візуальну підказку:

```
●●●●●●●●
●●●●●●●●
●●●●●●●●
●●●●●●●●
●●●●●●●●
●●●●●●●●
●●●●●●●●
```

Види підказок:

- групи предметів;
- числова пряма;
- розкладання множника;
- сусідній відомий приклад;
- переставна властивість: 8 × 7 = 7 × 8.

Правильну відповідь не потрібно миттєво показувати після першої помилки.
Краще:

1. Дати повторну спробу.
2. Показати легку підказку.
3. Після наступної помилки пояснити розв'язання.

## 7. Урізноманітнити завдання в сюжетних рівнях

Навіть у межах таблиці множення можна зробити значно більше, ніж
стандартне `7 × 8 = ?`.

Рекомендований розподіл:

| Тип | Приклад |
|---|---|
| Звичайний приклад | 7 × 8 = ? |
| Пропущений множник | 7 × ? = 56 |
| Правда чи помилка | 8 × 6 = 46 |
| Порівняння | 6 × 8 чи 7 × 7 |
| Ланцюжок | 4 × 5 + 6 |
| Обернене завдання | 56 ÷ 7 |
| Текстова задача | 6 кошиків по 7 яблук |
| Сортування | розстав результати за зростанням |
| Пошук пари | 7 × 8 ↔ 56 |
| Вибір дверей | результат написаний на проході |

Рівень може складатися, наприклад, із:

- 50% звичайних прикладів;
- 20% пропущених чисел;
- 15% порівнянь;
- 15% коротких задач.

## 9. Збереження прогресу — головний технічний ризик

localStorage підходить для невеликого локального прогресу, але воно
прив'язане до конкретного origin і браузера. Дані можуть зникнути після
очищення сховища, а в приватному режимі очищаються після завершення
приватної сесії. Обсяг Web Storage також обмежений; для самого прогресу
цього достатньо, але аудіо й великі ресурси там зберігати не потрібно.

### До запуску потрібно додати

**Версію збереження**

```json
{
  "saveVersion": 3,
  "createdAt": "...",
  "updatedAt": "...",
  "profile": {},
  "progress": {},
  "statistics": {}
}
```

**Міграції**

```js
migrateSave(save) {
  if (save.saveVersion === 1) {
    // migrate to v2
  }
  if (save.saveVersion === 2) {
    // migrate to v3
  }
  return save;
}
```

Інакше після зміни структури даних старі користувачі можуть втратити
прогрес або отримати помилки.

**Резервний snapshot**

Зберігати:

- `gameSaveCurrent`;
- `gameSaveBackup`.

Перед важливою зміною поточного збереження копіювати його в backup.

**Перевірку цілісності**

Якщо JSON пошкоджений:

1. Спробувати backup.
2. Показати зрозуміле повідомлення.
3. Не скидати все мовчки.
4. Запропонувати експортувати пошкоджені дані для діагностики.

**Експорт та імпорт**

Файл: `kingdom-math-save-2026-07-31.json`

Це частково розв'яже проблему перенесення між пристроями до появи
акаунтів.

## 12. Доступність

Для публічного запуску варто орієнтуватися на WCAG 2.2 AA. Мінімальний
контраст звичайного тексту має бути 4.5:1; інтерактивні елементи повинні
мати видимий keyboard focus, логічний порядок фокусу та достатню область
натискання. Для власного внутрішнього стандарту краще робити кнопки не
меншими за 44×44 CSS px, що перевищує мінімальну вимогу WCAG AA й
зручніше для дітей на сенсорних екранах.

Перед запуском перевірити:

- керування клавіатурою;
- aria-label для кнопок-іконок;
- видимий focus-visible;
- контраст золотого тексту;
- контраст приглушених завершених завдань;
- правильний порядок читання screen reader;
- відсутність інформації лише через колір;
- режим prefers-reduced-motion;
- можливість вимкнути музику і звуки.

Анімації, що виникають після взаємодії, бажано вимикати або суттєво
скорочувати для користувачів із prefers-reduced-motion.

**Частково реалізовано (04.08.2026) — кодовий аудит.** Загалом
дизайн-система вже мала непогану базу (aria-label на більшості кнопок-
іконок, видимі focus-visible кільця на основних кнопках, форма входу з
aria-invalid/aria-describedby/role="alert"), тож основна робота — знайти
й закрити конкретні прогалини:

- `prefers-reduced-motion` раніше вимикав анімацію лише в кількох
  вибраних класах (auth-spinner, кілька ефектів на екрані результатів
  знань) — легко забути новий `@keyframes` при додаванні фічі. Додано
  один глобальний запобіжник (`*, *::before, *::after` →
  `animation-duration`/`transition-duration: 0.01ms !important` у
  `prefers-reduced-motion: reduce`), який покриває взагалі всі анімації
  гри одразу, без потреби перелічувати класи вручну. Жодна логіка в JS
  не чекає на `animationend`/`transitionend`, тож це безпечно.
- `.legal-footer-link:focus-visible` розрізняв фокус лише кольором тексту
  (без видимого кільця) — додано `box-shadow`-кільце, як в інших
  інтерактивних елементів.
- `LanguagePickerModal.jsx`, `BadgesModal.jsx` — не мали `role="dialog"`/
  `aria-labelledby` і не закривались по Escape; переведені на спільний
  `useModalDialog` (той самий хук, що вже використовували install-
  модалки — Escape, фокус на перший елемент, повернення фокусу, id для
  aria-labelledby).
- `ExitConfirmModal.jsx` (підтвердження виходу з рівня) — навмисно не
  закривається кліком по фону (щоб не втратити прогрес випадковим тапом
  повз кнопки), але Escape усе одно мав спрацьовувати як найбезпечніша
  дія — раніше не спрацьовував. Додано (мапиться на "Продовжити", а не
  на вихід).
- `MemoryScreen.jsx` — кнопка "назад" (←) була без `aria-label`, хоча
  такі самі кнопки в GameScreen/MazeScreen/RaceScreen уже мали. Вирівняно.
- Контраст: порахував за формулою WCAG кілька приглушених текстових
  класів на реальному фоні (`#1e1b4b`). `text-violet-300/60`
  (auth-screen підказка, "прогрес зберігається" підпис у налаштуваннях)
  давав 4.02:1 — трохи нижче порогу 4.5:1 для звичайного тексту; підняв
  до `/80` (6.04:1). Приглушений текст заблокованих рівнів на карті
  (`text-white/40`, 3.67:1) НЕ чіпав — це текст усередині `disabled`-
  кнопки, а неактивні елементи керування прямо виключені з вимоги
  контрасту WCAG 1.4.3.

Не встигли: повний скрін-рідер прогін (VoiceOver/TalkBack) реальними
руками — це вже не можна перевірити кодом, тільки на пристрої.

## 13. Продуктивність

Гра має багато PNG, фонів, аватарів, музики й звуків. На слабкому
телефоні це може спричинити:

- довгий перший запуск;
- зависання під час переходів;
- запізнення звуку;
- стрибки інтерфейсу;
- велике використання пам'яті.

Орієнтири хорошої вебпродуктивності: LCP не більше 2.5 секунди, INP не
більше 200 мс і CLS не більше 0.1 для більшості користувачів.

Що зробити:

- оптимізувати всі PNG;
- генерувати кілька розмірів великих фонів;
- використовувати WebP/AVIF для непрозорих пейзажів;
- залишити PNG для зображень із прозорістю;
- lazy-load аватари магазину;
- не завантажувати всі 36 звуків на першому екрані;
- завантажувати звуки режиму перед його запуском;
- preload лише головного фону, активного аватара і базових UI-іконок;
- резервувати розміри зображень, щоб блоки не стрибали;
- розділити JS по маршрутах;
- уникати важких blur та glow на великій кількості елементів одночасно;
- тестувати FPS на реальному бюджетному Android.

## 14. Зробити PWA

Для такої гри PWA дуже доречна:

- користувач може встановити її на домашній екран;
- гра відкривається без браузерної панелі;
- базові ресурси можна кешувати;
- частину гри можна запускати без інтернету.

Для встановлюваної PWA потрібен Web App Manifest; service worker можна
використати для offline-сторінки та кешування критичних ресурсів.

Додати:

- `manifest.webmanifest`
- `service-worker.js`
- `icons/icon-192.png`
- `icons/icon-512.png`
- `icons/maskable-512.png`

Також:

- `theme_color`;
- `background_color`;
- `display: standalone`;
- offline fallback;
- екран «Доступне оновлення»;
- кнопку «Встановити гру», коли браузер це підтримує.

Не кешувати старий JS назавжди. Потрібна контрольована стратегія
оновлення, щоб користувачі не залишалися на застарілій версії.

**Реалізовано.** `public/manifest.webmanifest` (name/short_name, icons
192/512/maskable-512, `theme_color`/`background_color` #1e1b4b,
`display: standalone`), підключено в `index.html` разом із
`<meta name="theme-color">`. `public/service-worker.js` — рукописний, без
build-плагіна: navigation — "network first" (завжди свіжий index.html,
коли є мережа, кеш лише як fallback — вимога "не кешувати старий JS
назавжди" виконана явно), `/assets/*` + шрифти — "stale while
revalidate". `public/offline.html` — fallback-сторінка, коли взагалі
немає ні мережі, ні кешу. Оновлення НЕ застосовується автоматично: нова
версія чекає в стані "waiting", `UpdateBanner.jsx` показує
"Доступне оновлення" з кнопкою "Оновити" (шле `SKIP_WAITING`, чекає
`controllerchange`, тоді reload) — щоб дитину не перекинуло посеред
бою.

Сценарій встановлення (технічне ТЗ від 04.08.2026) — жодних технічних
термінів на екрані (не "beforeinstallprompt", не "PWA", не "manifest", не
"не підтримується"), лише прості формулювання. Уся розгалужена логіка
винесена в `src/hooks/useInstallFlow.js`, яким користуються і постійна
кнопка в попапі налаштувань (`MenuScreen.jsx`), і ненав'язливий банер
після перемоги (`InstallBanner.jsx`, рендериться в `ResultsScreen.jsx`):

- **Android/Chromium** — подія `beforeinstallprompt` (лише в
  `src/game/pwa.js`, `preventDefault()` + збереження, ніякого автопопапу)
  вмикає кнопку "Встановити гру"; клік викликає системний діалог
  (`event.prompt()`); після `appinstalled` кнопка зникає.
- **iOS Safari** — такої події не існує в принципі, тож кнопка веде на
  `IosInstallModal.jsx`: побутова покрокова інструкція "Поділитися →
  На початковий екран → Додати" зі схематичною ілюстрацією (не скриншот
  Safari, щоб не застаріти), кнопки "Зрозуміло"/"Не зараз".
- **iOS, але не Safari** (Chrome/Instagram-вебвʼю тощо — виявляється по
  UA-токенах `CriOS`/`FxiOS`/`Instagram`/... в `isIosSafariBrowser()`) —
  там пункту "На початковий екран" часто взагалі нема, тож
  `OpenInSafariModal.jsx` пропонує спершу скопіювати посилання
  (`navigator.clipboard`, з textarea+`execCommand` фолбеком для
  вебвʼю, де clipboard API заблоковано) і відкрити сторінку в Safari.
- **Вже встановлено** (`isAppInstalled()` — `display-mode: standalone`
  або iOS-специфічний `navigator.standalone`) — кнопка, банер і всі
  модалки просто не рендеряться.
- Без окремого банера — лише постійна кнопка "Встановити гру" в попапі
  налаштувань (`canShowInstallSuggestion()`/`dismissInstallSuggestion()`
  у `src/game/pwa.js` лишились у коді про запас, але зараз нічого не
  викликає їх — банер на головному екрані прибрали за прямим проханням).
- Модалки: `role="dialog"`, `aria-modal`, `aria-labelledby`, Escape на
  десктопі, фокус повертається на кнопку-тригер, внутрішня прокрутка на
  малих екранах (`max-h-[88dvh] overflow-y-auto`) — спільна логіка в
  `src/hooks/useModalDialog.js`.

## 15. Аналітика без порушення приватності

Без аналітики після запуску не буде видно:

- чи проходять tutorial;
- де виходять;
- який рівень занадто складний;
- який режим майже не запускають;
- які приклади найважчі;
- чи повертаються наступного дня.

### Мінімальні події

- `app_open`
- `tutorial_started`
- `tutorial_completed`
- `diagnostic_completed`
- `level_started`
- `level_completed`
- `level_failed`
- `answer_submitted`
- `hint_used`
- `avatar_purchased`
- `training_started`
- `race_difficulty_selected`
- `race_finished`
- `save_exported`
- `app_error`

Для відповідей:

```json
{
  "skillId": "multiply_7_8",
  "correct": false,
  "responseTimeBucket": "3-5s",
  "mode": "battle",
  "levelId": "forest_gate"
}
```

Не передавати:

- ім'я дитини;
- дату народження;
- точну адресу;
- контакти;
- текстові повідомлення;
- рекламний ідентифікатор.

Найбезпечніший старт — агрегована або self-hosted аналітика без
рекламних профілів. Якщо додається будь-яке відстеження користувачів,
його потрібно окремо перевірити з погляду правил дитячої приватності.

**Реалізовано (лише фронтенд).** `src/config.js` — `ANALYTICS_ENABLED`
(за замовчуванням `false`, той самий підхід, що й `AUTH_ENABLED`) і
окремий `ANALYTICS_ENDPOINT` (навмисно НЕ той самий бекенд, що
`VITE_API_URL` — акаунти/синхронізація прогресу й далі заморожені за
попереднім рішенням, аналітика від них не залежить і не вимагає
входу). `src/game/analytics.js` — `trackEvent()` є повним no-op, поки
прапорець вимкнено (нічого не пишеться навіть у localStorage); коли
увімкнено — події чергуються локально (з обмеженням розміру) і батчами
йдуть на `ANALYTICS_ENDPOINT` (fetch з ретраєм, `sendBeacon` на
`pagehide`/приховану вкладку); без заданого endpoint черга просто
накопичується локально й нікуди не йде. Підключено 14 із 15 подій зі
списку вище: `app_open`, `tutorial_started`, `tutorial_completed`,
`diagnostic_completed`, `level_started`, `level_completed`,
`level_failed`, `answer_submitted` (skillId/correct/
responseTimeBucket/mode/levelId — без точного часу), `hint_used`,
`avatar_purchased`, `training_started`, `race_difficulty_selected`,
`race_finished`, `app_error` (лише узагальнена назва класу помилки,
без message/stack). `save_exported` — НЕ підключено: наразі в
застосунку немає UI для експорту збереження у файл (сама функція
export/import ще не винесена на жоден екран), тож тригера для цієї
події поки не існує.

Щоб система реально запрацювала: (1) підняти окремий self-hosted чи
агрегований сервіс прийому подій, (2) виставити
`VITE_ANALYTICS_ENDPOINT` і `VITE_ANALYTICS_ENABLED=true` в `.env`, (3)
окремо перевірити цей сервіс із погляду дитячої приватності, як і
зазначено вище.

  `OpenInSafariModal`, `BadgesModal`) — нижній відступ не враховував
  `safe-area-inset-bottom`, кнопки могли опинитись впритул до смуги
  жесту "додому". Додано `pb-[max(1.5rem,env(safe-area-inset-bottom))]`
  (лише на мобільній `items-end`-розкладці, на `sm:` — назад до
  звичайного відступу).
- Toast-компоненти, закріплені до країв екрана (`UpdateBanner`,
  `SaveNoticeToast` — низ; `SimpleToast`, `BadgeToast` — верх) — так само
  не враховували safe-area, виправлено.
- Замалий тап-таргет: кнопка закриття картки "прогрес зберігається"
  (24×24px → 36×36px), X-кнопка `AvatarPurchaseModal` (32×32px →
  40×40px), перемикачі "Музика"/"Звуки" в налаштуваннях — раніше сам
  повзунок був єдиною клікабельною зоною (44×24px), тепер клікабельний
  увесь рядок (як інші пункти того ж попапу).
- Ігрові тап-зони (клітинки лабіринту, картки пам'яті, кнопки відповідей
  битви, картки перегонів) уже мали з запасом ≥64px — без змін.
- Текстові поля (`AuthScreen`) уже на `text-base` (16px) — безпечно від
  автозуму iOS Safari при фокусі, без змін.
- `overflow-x: hidden` на `html/body` вже стоїть глобально — це
  запобіжник від горизонтального скролу навіть якщо якийсь елемент
  (напр. банер "Щоденні завдання" з `whitespace-nowrap` у довших мовах
  типу угорської/німецької) візуально не поміститься на 320px екрані.
- НЕ чіпали: паттерн блокування прокрутки модалок через
  `body.style.overflow = "hidden"` — на iOS Safari це не ідеально
  (можливий незначний bounce фону), але це вже наявний, широко
  використовуваний паттерн у багатьох модалках; переписувати його на
  `position: fixed` + збереження scrollY — це окрема, ризикованіша задача
  поза межами цього аудиту.

- бонусні скрині.

**Витрати**

- аватари;
- рамки;
- підказки, якщо плануються;
- косметичні ефекти;
- майбутні теми профілю.

Перевірити:

- скільки приблизно проходжень потрібно для дешевого аватара;
- скільки для найдорожчого;
- чи не можна купити все за один вечір;
- чи не потрібні тижні для першої покупки;
- чи не дають перегони непропорційно багато;
- чи не фармиться daily reward зміною системного часу.

Для першого релізу економіка має бути щедрою. Дитина повинна відносно
швидко отримати першу покупку, щоб зрозуміти сенс монет.

## 20. Щоденні завдання треба зробити різноманітнішими

Зараз три завдання постійно однакові. Після кількох днів вони перестануть
бути цікавими.

Створити пул із 15–20 варіантів:

1. Дай 15 правильних відповідей.
2. Пройди 2 рівні.
3. Знайди 3 пари у пам'яті.
4. Відкрий скриню в лабіринті.
5. Посідай перше або друге місце в перегонах.
6. Дай 5 відповідей поспіль.
7. Повтори таблицю на 7.
8. Переможи без підказки.
9. Знайди секретний шлях.
10. Виконай 10 прикладів менше ніж за 4 секунди.
11. Покращ свій рекорд.
12. Виправ 3 слабкі приклади.

Щодня випадково обирати три завдання, але гарантувати:

- одне просте;
- одне середнє;
- одне пов'язане з тренуванням.

## 21. Досягнення також потрібно розширити

Наявні 8 досягнень хороші для старту, але їх швидко завершать.

Додати категорії:

**Навчання**

- 100 правильних відповідей.
- 500 правильних відповідей.
- Майстер таблиці на 7.
- Усі таблиці понад 80% mastery.
- 20 правильних поспіль.

**Пригоди**

**Наполегливість**

**Колекція**

- Перший придбаний аватар.
- 5 аватарів.
- Уся колекція.

Не всі досягнення повинні давати монети. Частина може давати:

- декоративний титул;
- рамку;
- ефект;
- спеціальний значок.

## 22. Контентний редактор

Коли з'являться дроби, рівняння й геометрія, рівні не повинні бути жорстко
зашиті в компонентах. Зараз варто перейти до data-driven структури:

```json
{
  "id": "forest-01",
  "regionId": "forest",
  "title": "Перші кроки",
  "skills": ["multiply-2", "multiply-3"],
  "questionTypes": [
    "direct",
    "missing-factor",
    "word-problem"
  ],
  "enemyId": "forest-worm",
  "questionCount": 8,
  "timeLimit": 10,
  "rewards": {
    "coins": 20,
    "xp": 35
  }
}
```

Генератори завдань:

- `multiplication`
- `division`
- `missingFactor`
- `comparison`
- `expressionChain`
- `wordProblem`

У майбутньому:

- `fractions`
- `decimals`
- `equations`
- `percentages`
- `geometry`
- `coordinates`

Так додавання нових 100 рівнів не вимагатиме копіювати логіку кожного
екрана.

## 27. Монетизація

Повна модель — в окремому документі `rekomendovana_model_monetyzatsii_math_rpg.md`.
Тут лише коротко, як вона стикується з рештою плану.

платні покупки з першого релізу — монетизація йде вже після нього, коли
є перший робочий безкоштовний продукт, реальні гравці й відгуки.

Коротко про рекомендовану модель:

- безплатне завантаження, без реклами;
- безплатна частина: перший регіон, 3–4 рівні, базове тренування, 1–2
  аватари, локальний прогрес;
- одноразова покупка **"Відкрити повну пригоду"** відкриває решту
  регіонів/режимів, хмарне збереження, синхронізацію між пристроями,
  сімейну статистику;
- рекомендована стартова ціна — 199 грн одноразово;
- покупка — лише через окремий батьківський розділ, за **parental
  gate** (не проста для випадкового натискання дитиною);
- кнопка "Відновити покупку" для перевстановлення/зміни пристрою.

**Залежності від інших розділів цього плану:**

- хмарне збереження й синхронізація в повній версії вимагають
  серверного прогресу — тобто спершу розділ 9 (збереження) і розділ 10
  (акаунти, зараз свідомо відкладені, `src/config.js:AUTH_ENABLED`) мають
  бути доведені до робочого стану;
- батьківський розділ і parental gate логічно лягають туди ж, де вже
  планується розділ 8 ("Додати окремий режим для дорослого");
- Android-публікація (`android-play-store-plan.md`) зараз рахує гру як
  `Price: Free` без платних розблокувань — перед стадією монетизації
  цей крок і Google Play Console (in-app purchase / paid app) потрібно
  буде переглянути окремо.

Порядок: спершу безкоштовний реліз і розділи 1–26 цього плану, потім
акаунти й серверна синхронізація, і лише тоді — монетизація за моделлю
з `rekomendovana_model_monetyzatsii_math_rpg.md`.
