# План публікації в Google Play (Android, через Capacitor)

**Виконувати ПІСЛЯ того, як легкий бекенд (`backend-mvp-plan.md`) готовий
і задеплоєний.** Реєстрація/логін, серверне збереження прогресу й HTTPS
API — передумова для кроків 5, 11 і 13 нижче (тестування логіну на
телефоні, Data Safety, видалення акаунта). Розділ "Рекомендований
порядок" наприкінці зводить усе в три послідовні етапи.

## Загальний шлях

```
React/Vite гра
      ↓
Capacitor
      ↓
Android Studio
      ↓
Signed Android App Bundle (.aab)
      ↓
Google Play Console
      ↓
Тестування
      ↓
Публікація в Google Play
```

## 1. Підготуй гру до Android

Перед складанням перевірити:

- [ ] backend працює через HTTPS;
- [ ] реєстрація, вхід і відновлення сесії працюють із телефона;
- [ ] кнопка Android Back не закриває гру випадково;
- [ ] немає горизонтального прокручування;
- [ ] враховано верхній і нижній `safe-area`;
- [ ] музика припиняється або приглушується після згортання;
- [ ] усі модалки та кнопки працюють на ширині 320–430 px;
- [ ] гра не відкриває Instagram чи інші зовнішні сторінки всередині
      невідомого WebView;
- [ ] є сторінки "Політика приватності", "Про гру" і "Видалити акаунт".

**Не робити застосунок, який просто відкриває URL сайту.** Google
забороняє дитячим застосункам бути лише оболонкою-WebView навколо
сайту. Через Capacitor зібрані файли гри вбудовуються всередину
Android-застосунку, а до інтернету звертатися лише для API й
синхронізації прогресу.

## 2. Додай Capacitor

У корені React/Vite-проєкту:

```bash
npm install @capacitor/core @capacitor/cli
npm install @capacitor/android
```

Ініціалізація:

```bash
npx cap init
```

Приклад значень:

```
App name: Королівство Математики
App ID:   com.ivanstepanowich.kingdommath
```

**`App ID` вибирати уважно** — після публікації змінити його для
наступних оновлень не можна: Google Play сприйме інший ID як зовсім
новий застосунок.

`capacitor.config.ts`:

```ts
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.ivanstepanowich.kingdommath',
  appName: 'Королівство Математики',
  webDir: 'dist',
};

export default config;
```

## 3. Створи Android-проєкт

```bash
npm run build          # спочатку зібрати сайт
npx cap add android     # додати Android-платформу
npx cap sync android     # скопіювати актуальну збірку
npx cap open android      # відкрити проєкт в Android Studio
```

Після кожної зміни React-коду:

```bash
npm run build
npx cap sync android
```

## 4. Встанови Android Studio

Потрібні:

- Android Studio;
- актуальний Android SDK;
- JDK, який рекомендує поточна версія Android Studio;
- емулятор або фізичний Android-телефон.

Перевірити `android/app/build.gradle`, приклад версії першого релізу:

```gradle
defaultConfig {
    applicationId "com.ivanstepanowich.kingdommath"
    versionCode 1
    versionName "1.0.0"
}
```

Для кожного наступного завантаження збільшувати:

```gradle
versionCode 2
versionName "1.0.1"
```

**Target SDK.** Станом на 3 серпня 2026 нові застосунки ще мають
відповідати Android 15/API 35, але з 31 серпня 2026 Google Play
вимагатиме Android 16/API 36 для нових застосунків та оновлень. Для
першого релізу доцільно одразу цілитися в API 36, якщо актуальна
версія Capacitor і Android Gradle Plugin його підтримують (звірити
безпосередньо перед реалізацією цього кроку — вимога й підтримка
можуть змінитися).

## 5. Протестуй на справжньому телефоні

`Run → Run 'app'` в Android Studio. Обов'язково перевірити:

- [ ] реєстрацію;
- [ ] login/logout;
- [ ] refresh авторизації після перезапуску;
- [ ] збереження прогресу;
- [ ] музику та SFX;
- [ ] покупки аватарів за внутрішні монети;
- [ ] системну кнопку Back;
- [ ] переходи за зовнішніми посиланнями;
- [ ] поведінку без мережі;
- [ ] повільний інтернет;
- [ ] поворот екрана;
- [ ] нижню системну панель Android;
- [ ] відновлення гри після згортання.

**Окремо перевірити CORS бекенду.** Для Android-збірки запити Capacitor
можуть виходити з локального origin застосунку — сервер має дозволяти
потрібні origin і `credentials`, але ніколи не `origin: '*'`.

## 6. Створи ключ підпису

В Android Studio: `Build → Generate Signed Bundle / APK → Android App
Bundle → Create new`.

Створити файл, напр. `kingdom-math-upload-key.jks`, і окремо зберегти:

- `.jks` файл;
- alias;
- пароль key store;
- пароль ключа.

**Не завантажувати їх у GitHub.**

Google Play вимагає підписаний Android App Bundle — нові застосунки
завантажуються у форматі `.aab`, Play App Signing обов'язковий для
нових застосунків. Файл з'явиться приблизно тут:
`android/app/release/app-release.aab`.

## 7. Створи Google Play Console

Потрібно: Google-акаунт → реєстрація в Play Console → підтвердження
особи й контактних даних → одноразова оплата $25.

Тип акаунта: **Personal account** (особистий) підійде для першого
власного проєкту; **Organization account** — для офіційної компанії
(потрібен D-U-N-S номер).

## 8. Створи застосунок у Play Console

`Home → Create app`:

```
Назва:          Королівство Математики
Тип:            Game
Ціна:           Free
Основна мова:   Українська
```

Плюс контактна email-адреса. Обмеження: назва застосунку — 30
символів, короткий опис — 80, повний опис — 4000.

## 9. Підготуй сторінку в магазині

- **Іконка Google Play** — 512×512 px, PNG, до 1 МБ.
- **Feature graphic** — 1024×500 px, PNG або JPEG, без прозорості.
- **Скриншоти** — 5-8 штук: головний екран, карта королівства, бій,
  математична пам'ять, лабіринт, перегони, "Мої знання", магазин або
  досягнення.

## 10. Дитяча аудиторія

Гра розрахована на дітей 10–12 років. У `Policy and programs → App
content → Target audience and content` — чесно обрати відповідну
дитячу вікову групу. Наявність дитячої аудиторії означає відповідність
Google Play Families Policy (Google оцінює дизайн, персонажів і
формулювання, не лише форму).

Для першого релізу краще:

- [ ] без реклами;
- [ ] без чату;
- [ ] без публічних профілів;
- [ ] без глобального рейтингу дітей;
- [ ] без збору справжнього імені, школи, телефону чи адреси;
- [ ] без непотрібних Android permissions;
- [ ] без рекламного ID.

## 11. Privacy Policy і Data Safety

Оскільки застосунок використовує логін, пароль, user ID й серверне
збереження прогресу — дані вже передаються за межі пристрою.

У Play Console заповнити **Data safety**, описавши всі дані, які
збирає бекенд і сторонні SDK — потрібно навіть для тестових релізів
(крім винятково внутрішнього тестування). Навіть застосунки без збору
даних мають заповнити форму й мати privacy policy.

Privacy Policy має бути:

- за публічною HTTPS-адресою;
- додана в Play Console;
- доступна всередині самої гри;
- узгоджена з Data Safety.

Оскільки застосунок дозволяє створювати акаунт, потрібно також:

- видалення акаунта всередині застосунку;
- вебпосилання для видалення/запиту на видалення;
- фактичне видалення пов'язаних даних, не лише блокування профілю.

Тому до публікації бекенд варто доповнити:

```
DELETE /api/v1/account
```

і сторінкою `https://твій-домен/account-deletion`.

## 12. Завантаж `.aab`

`Release → Testing → Internal testing → Create new release` — спочатку
завантажити `app-release.aab`, додати release notes (напр. "Перша
тестова версія гри. Додано сюжетні рівні, тренування, прогрес і профілі
користувачів."). Почати з Internal testing, щоб перевірити встановлення
через справжній Google Play.

## 13. Обов'язкове закрите тестування

Якщо це новий Personal developer account, створений після 13 листопада
2023 — перед доступом до Production потрібен closed test: щонайменше
12 тестувальників, підключені щонайменше 14 днів безперервно.

Практично:

1. Створити Google Group або список email.
2. Додати 12-15 знайомих.
3. Створити Closed testing release.
4. Надіслати opt-in посилання.
5. Тестувальники встановлюють гру через Google Play.
6. Не виходять із тесту 14 днів.
7. Зібрати короткі відгуки.
8. Після завершення — заявка на Production access.

Для дитячого продукту краще, щоб акаунти й встановлення контролювали
дорослі (колеги, знайомі, батьки).

## 14. Подання на Production

`Release → Production → Create new release` — завантажити той самий чи
новіший `.aab`, заповнити release notes, відправити на review.

Перед кнопкою Submit мають бути завершені: Store listing, App access,
Ads declaration, Content rating, Target audience, Families declaration,
Data safety, Privacy policy, Account deletion, Government apps
declaration, Financial features declaration, країни розповсюдження,
ціна, тестування, Play App Signing.

## Рекомендований порядок

**Етап 1 — зараз (бекенд, `backend-mvp-plan.md`)**

1. Доробити register/login.
2. Додати серверне збереження.
3. Додати видалення акаунта (`DELETE /api/v1/account`).
4. Написати Privacy Policy.
5. Задеплоїти backend через HTTPS.

**Етап 2 — Android**

6. Додати Capacitor.
7. Згенерувати Android-проєкт.
8. Виправити Android Back і safe-area.
9. Протестувати login та збереження на телефоні.
10. Згенерувати signed AAB.

**Етап 3 — Google Play**

11. Створити Play Console.
12. Підтвердити особу.
13. Створити сторінку гри.
14. Завантажити іконку, feature graphic і скриншоти.
15. Заповнити Families, Data Safety та Content Rating.
16. Запустити Internal testing.
17. Провести Closed testing: 12 тестувальників / 14 днів.
18. Подати застосунок у Production.

Найкращий варіант для цієї гри: React/Vite + Capacitor + Android
Studio + `.aab`. Переписувати інтерфейс не потрібно — код, дизайн,
бекенд і більшість логіки лишаються як є.
